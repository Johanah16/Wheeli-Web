# Wheeli portal decks (Resvita)

Wheeli is Resvita's member portal, a brand "powered by Resvita". This folder builds it as single-file HTML **decks**: one page with tabs that embeds every tool. There are three kinds:

- **Wheeli deck** (`Wheeli-Deck.html`): the generic demo, in blue `#3D7BF7`. Its Coach view lists every client.
- **Murphy's deck** (`Murphys-Construction-Deck.html`): the worked example for Lance at Murphy's Construction Co., in green `#77B84A`.
- **Client decks**: one per client in `source/clients.py`, in the client's own brand.

Josh Waldrom (Resvita) owns the project and signs off on the design.

## Build

```bash
python3 -I source/build_all.py          # from this folder: builds every page and every deck
```

- Python 3 standard library only. Each `source/build_*.py` writes pages to this folder, and `build_deck.py` embeds them (base64) into the decks.
- `build_all.py` runs them in dependency order. To build part of it (e.g. after editing a Rocket fuel panel), run `build_rocket.py` then `build_deck.py`.
- Built pages and decks are **not** in Git (see `.gitignore`), so build after every pull. The one exception is **`Wheeli-Deck.html`**, Resvita's own deck, kept in Git so the team can open it straight from GitHub (Josh, 4 Nov 2026): after changing anything, rebuild and commit it too, or it falls behind.
- Never edit a built `*.html` in this folder. Edit the template or panel in `source/` and rebuild.

Map of `source/`:
- `*-template.html` are the pages and `*-panel.html` are the features injected into them (e.g. `pablo-panel.html` on Rocket fuel, `coach-panel.html` the Coach view).
- `build_deck.py` holds the tab order, the Focused-view config (`VIEWS`), and the Coach roster (`ROSTER`).
- `clients.py` holds the client entries and the helpers used to write them.
- `HOW-TO-EMBED.md` covers hosting, installing on a phone, and every feature in user terms.
- `BACKEND-TODO.md` lists every saved store and what the backend does with it; add a line to its Recent additions whenever a change adds or changes saved data.

## Working together (Josh + Johanah, from 4 Nov 2026)

Josh keeps adding features (with Claude) while Johanah builds the backend and makes Wheeli live. These rules keep the two from tripping over each other:

1. **GitHub `main` is the one source of truth.** Josh's front-end work is committed to `main` in small pieces and pushed often. Johanah works on her own branch (e.g. `backend`), pulls `main` into it every day or two, and merges back into `main` when a piece is ready.
2. **Separate files where possible.** Front end: `source/` (templates, panels, `lessons.json`, build scripts). Backend: a new `backend/` folder, plus one thin storage layer in `source/` that sends the `<brand>-…` saves to the cloud instead of the browser. Files both may touch: `hub-panel.html`, `coach-panel.html`, `build_deck.py`: say so in chat when you change one.
3. **`Wheeli-Deck.html` is only committed from `main`, after a rebuild.** It changes with every edit, so it always conflicts: never merge it by hand, just run `build_all.py` again. Johanah doesn't commit it from her branch.
4. **Every change that saves data gets a line in `BACKEND-TODO.md` › Recent additions** (which store, what it holds), and every store is listed there by what the backend has to do. Claude does this with each change; Johanah works through it.
5. **Staging before live.** Johanah publishes `main` to a test address first; Josh and a coach check it; then it goes to members.
6. **Once the backend is live, content stops being code.** Lessons and Platform content save straight to the backend from the Coach view, with no file or rebuild.

When a change lands, Josh drops Johanah a one-liner (e.g. "pushed: Proven Playbooks as cards, no new data").

## Adding a client

0. **Usually starts in the Wheeli deck:** Coach view › ➕ New client (logo, brand colour with a live header preview, business, people, programme, coaches, tools, services and jobs for the brain). It downloads `wheeli-client-<key>.json`; run `python3 -I source/add_client.py <file>` to save the logo and setup to `source/clients/new/<key>.json` and print the remaining steps below.
1. Josh sends their website. Pull the logo into `source/clients/<key>-logo.png`, sample the brand colour, and read their services.
2. Add an entry to `CLIENTS` in `source/clients.py`. Copy a similar trade and use the helpers (`client()`, `std()`, `swaps()`, …). `replace` swaps the Wheeli example wording (written for a bathroom renovator) into their trade.
3. Add their brain profile (3 services, 3 facts, 5 jobs) to `BRAIN` in `source/build_client_brains.py`.
4. Make app icons in `app-icons/` (`tools/images/icon.swift`).
5. Run `build_all.py`, then check the deck. In particular check the logo size on Home: it should be about the height of 365 Alongside's or Cool Innovations'.
6. Write their tour script and record the welcome video (`tools/README.md`).
